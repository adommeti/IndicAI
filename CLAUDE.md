# indic-ai-platform — working agreement

## What this repo is
One shared Python platform (`platform/`, imported as `indic_platform`) plus three FastAPI apps
(`apps/helpdesk_agent`, `apps/training_localizer`, `apps/comms_surveillance`). Sarvam (speech,
translation, dubbing) and Anthropic (Claude) are consumed ONLY through `platform/adapters/`.
Apps never import vendor SDKs directly. The specification is `docs/prd-v2.md` (read-only; record
deviations as ADRs in `docs/adr/`). The build is executed as an ordered series of prompts under
`prompts/` tracked in `docs/build/PROMPT-PLAN.md`; the operating procedure is `docs/build/RUNBOOK.md`.

## Non-negotiables
- Python 3.12, uv workspace, FastAPI, LangGraph, Celery, PostgreSQL 16 (+pgvector), Qdrant, Redis,
  MinIO, LiveKit, Pipecat, React + Vite + Tailwind. No .NET. Open source everywhere except the two
  model vendors.
- Every Claude call with a stable system prompt uses prompt caching; temperature 0 for structured
  output; outputs validated with pydantic; `model` and `prompt_version` recorded on persisted rows.
- Untrusted content (utterances, transcripts, documents, scripts) is wrapped with
  `indic_platform.security.harden.wrap_untrusted` and labeled as data in every prompt. Analysis
  calls in `comms_surveillance` have NO tools.
- `indic_platform.security.redact.redact` runs before text reaches a vendor or a log, unless an app
  documents an override in its README.
- No secrets in the repo. Keys come from the environment; `.env.example` lists every variable.
  `.env` and `.env.stack` are never read or edited by the agent.
- Tests: pytest + pytest-asyncio. Vendor calls are mocked by default. Live-API tests are marked
  `slow` and run only with `LIVE_API_TESTS=1`; tests needing the Docker stack are marked
  `integration`.
- Migrations via alembic. Never edit a shipped migration; add a new revision.
- Observability: every adapter call emits a Langfuse span (metadata only) with latency, units and
  INR/USD cost from `platform/config/pricing.yaml`.
- Golden-set labels are never changed to make an evaluation pass. Missing data is reported as
  "unmeasured", never given a passing placeholder.

## How work flows (autonomous)
1. Start a prompt: `bash scripts/run-prompt.sh <uc1|uc2|uc3|program> <Pn>` — creates
   `build/<uc>-<pn>` off the base branch and prints the prompt to execute.
2. Build it. Prefer domain model first (entities, invariants), then adapters/services, then API,
   then UI. Write tests alongside code. Use subagents in `.claude/agents/` for review and evals.
3. Verify: `make check` (lint, typecheck, unit tests, offline evals, attribution, secrets) must be
   green; run the prompt's `make eval-ucN` / integration / live checks as its acceptance requires.
4. Report: write `.claude/run/report.md` restating every acceptance criterion with pass/fail and
   the measured numbers; list anything not done and why. Update the prompt's row in
   `docs/build/PROMPT-PLAN.md` (`status`, `merged` columns) in the same branch.
5. Ship: commit with a plain conventional message, then `bash scripts/ship.sh`. It runs the gate,
   rebases, pushes, opens the PR, waits for CI, squash-merges and returns to the base branch.
   If CI is red, fix it and re-run ship. Never merge any other way.
6. Do not stop with uncommitted or unmerged work while a prompt is active. The Stop gate enforces
   this. Do not proceed to the next prompt unless the message that started the session asked for
   a range of prompts.

## When something cannot be done
Do not silently narrow scope. Implement what is possible, keep the acceptance criterion marked
FAIL/UNMEASURED in the report, add an entry to `docs/build/BLOCKERS.md` (what, why, what is needed),
and still ship the rest. Vendor keys missing → live steps are skipped and listed as blocked.

## Commit and PR conventions
- Author and committer are always the repository owner; identity is pinned by the session hook.
  Messages are plain, imperative, conventional (`feat(uc1): add guard node`), with no trailers,
  footers, emoji, tool names or session links. Repo hooks and CI reject anything else.
- One PR per prompt, squash-merged. PR body = summary + verification report; generated by ship.sh.

## Useful commands
- `make check` / `make check-full` — gate / gate + integration + audit (`scripts/checks.sh`)
- `make stack-core` (postgres, redis, qdrant, minio, tei) · `make stack-obs` · `make stack-voice` ·
  `make stack-sparse` · `make up` (all) · `make stack-status`
- `make migrate`, `make ingest-kb`, `make eval-uc1|uc2|uc3`, `make voice-test`
- `LIVE_API_TESTS=1 uv run pytest -m slow -k <subset>` — live vendor smoke (costs money; keep narrow)
- `bash scripts/run-prompt.sh --status` — plan status

## MCP servers available in-session
- `sarvam` — Sarvam STT/TTS/translate/transliterate/dubbing tools. Use it to synthesize golden
  audio and to confirm request/response shapes before touching an adapter.
- `context7` — current library docs (LangGraph, Pipecat, LiveKit, Qdrant, Celery, SQLAlchemy).
  Consult it before using an API you are not certain about.
